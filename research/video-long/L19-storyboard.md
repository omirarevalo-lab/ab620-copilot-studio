## Fact notes (checked)
- Errors in a flow are not an "if", they are a "when"; handling them is a plan B so the flow knows what to do instead of staying silent; the classic pattern is try-catch — theory L19 intro.
- Scope = container that groups actions so they can be handled together; main actions in a scope Try, another scope Catch right after it to handle the error — theory "Try and Catch with scopes"; glossary "Scope"; steps 2-3.
- Run after defines when an action runs based on the result of the previous one; set on the Catch relative to the Try with has failed and has timed out; it can check failed, timed out, skipped or succeeded — theory "Try and Catch with scopes", "Run after: the trap"; glossary "Run after".
- Trap: is successful makes the Catch run only when everything went well — theory "Run after: the trap"; exam tips.
- result() returns the results of the actions in the Try scope; Filter array keeps the one that failed; log the error or notify someone (IT) — theory "Reading the error"; steps 5-6; example. "Some succeeded and one failed" is the illustrative case of the example (the Dataverse insert fails).
- Retry policy for transient failures, set in the action settings with an initial interval and a maximum number of retries; exponential preferred because it increases the interval between retries — theory "Retry policy and Terminate"; glossary; exam tips. "1 min · 2 min · 4 min" only as the theory's illustrative visual.
- Terminate with status Failed and a message stops the flow and leaves a diagnosis — theory "Retry policy and Terminate"; glossary "Terminate"; exam tips.
- Contoso case: CreateTicket, Dataverse insert in Try, Catch on has failed and has timed out, result() and Filter array for the exact message, log it, notify IT, Terminate Failed; external service call with exponential retry because sometimes the network fails for a moment and a later retry works — theory L19 example.
- Studio steps (scene 9 only those): open the agent flow in the designer; add scope Try with the main actions; add scope Catch right after; run after has failed and has timed out in the Catch settings; Filter array on result() of the Try; log or notify IT and Terminate with status Failed and a message; exponential retry policy on sensitive actions — theory L19 steps.
- Exam distractors "Is successful and is skipped", "Is skipped and has timed out", "A Terminate with status Failed", "A Catch with is successful", "An exponential retry on every action" and "A Catch that runs after is successful" are wrong choices only; the video claims nothing about them beyond the theory.
