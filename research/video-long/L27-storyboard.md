## Fact notes (checked)
- MCP = Model Context Protocol, an open protocol that lets a server offer tools and resources to any compatible agent; universal plug, no special adapters; Copilot Studio is one client; the agent only reads which tools are offered — theory intro, "What an MCP server is"; glossary "MCP".
- MCP requires generative orchestration; the orchestrator chooses tools based on their description — theory "What an MCP server is"; exam tips; glossary "Orchestrator"; step 1.
- Only Streamable HTTP; SSE not supported since August 2025; an SSE-only server will not work — theory "Allowed transport"; exam tips; glossary "Streamable HTTP".
- Wizard path Tools, Add a tool, New tool, Model Context Protocol; name, description (used by the orchestrator to decide when to call), server URL — theory "Two ways to connect"; steps 2-4.
- Custom connector in Power Apps from an OpenAPI file (Swagger 2.0), POST /mcp with x-ms-agentic-protocol: mcp-streamable-1.0 — theory "Two ways to connect"; exam tips.
- Authentication None, API key (Header or Query), OAuth 2.0 (Dynamic discovery, Dynamic, Manual); then create the connection and Add to agent — theory "Authentication and governance"; steps 5-7.
- DLP governs MCP because MCP uses Power Platform connectors; blocks unapproved servers — theory "Authentication and governance"; example; exam tips.
- Allow all on by default (new tools enabled automatically); off → enable one by one, new tools disabled until a maker enables them; least privilege, fewer tools — theory "Managing tools, resources, and keys"; glossary "Allow all"; exam tips.
- Descriptions read-only, fix with the server owner; resources only as output of an MCP tool; MCP prompts not supported; updates seen with no republish; topics can't call MCP — theory "Managing tools, resources, and keys".
- API key: maker sets Type (Header or Query) and Parameter name (e.g. x-api-key), does not store the key; each user is asked for their own key the first time — same section.
- Example: nexo-tools gets and creates support tickets; wizard with name, description "Gets and creates tickets", URL; connection, Add to agent; printer failure → orchestrator calls the create ticket tool; security team blocks unapproved servers with a data policy — theory example. The "get ticket" card is only the get half of "gets and creates tickets".
