## Fact notes (checked)
- Multi-agent design answers "where do I put each capability?"; options child agents, connected agents, external agents — theory intro.
- Child agent: inside the main agent, lightweight, single use case and team, no settings, authentication or deployment of its own, not published separately — theory "Child agent: light and inside"; glossary "Child agent".
- Default routing "The agent chooses, Based on description"; "When will this be used?" triggers (full list as in the theory); Condition (builder or Power Fx) and Priority; An activity occurs first, The agent chooses last; lower number = higher priority — theory "Child agent: light and inside". The spoken scene names three triggers; the board shows all nine.
- Connected agent: another Copilot Studio agent in the same environment, own publishing and life cycle; orchestrator chooses by descriptions; must be published, same environment, set to allow other agents to connect — theory "Connected agent: separate"; glossary.
- External: A2A, Microsoft Foundry, Fabric data agents, Microsoft 365 Agents SDK — theory "Connected agent: separate"; exam tips.
- Harness: standard = Copilot Studio (yes), Foundry / Fabric / Agents SDK (preview), A2A (yes), child agents; Microsoft Copilot harness = connected Copilot Studio agent only (itself a Microsoft Copilot harness agent); building blocks Redirect node, Run an agent in an agent flow, Power Automate cloud flow with Microsoft Copilot Studio connector (Execute Agent and wait); Microsoft Copilot harness workflow uses the agent node — theory "Connected agent: separate" and "Choosing a coordination pattern".
- Split rule: more than 30 to 40 options across tools, topics and agents, or similar descriptions; also teams, channels, own settings, independent ALM, reuse; start with one agent, smallest change first (distinct descriptions and instructions, or add a tool or knowledge source) — theory "When to split"; steps 1-5.
- Cost: each hop adds latency and enlarges what to test and govern; governance: least privilege, only the needed context, human approval for high-impact cross-agent actions, end-to-end traceability — theory "The cost"; exam tips.
- Patterns: key question "how much of the path is known before runtime"; orchestrator/subagent = runtime choice, open-ended, wrong for consistent success rate or strict ordering; workflow-oriented = deterministic, approval gates, auditability; serial (strict order, slower), concurrent (parallel, quorum or voting); mix both — theory "Choosing a coordination pattern"; glossary; exam tips.
- Example: licenses = child agent inside the IT agent (one team, one use case); human resources = connected agent (own team, channels, publishing); options passed 30 to 40 and descriptions looked alike; accepted the cost of one more orchestration call — theory example.
- Story setting only: Marta's holiday question, Nexo's printer and ticket signs (from L27), the new hire process and its manager approval, the "few tools and topics" in exam 2. Distractors "As one more topic in the IT agent", "Give every request its own child agent", "A concurrent workflow that votes" are wrong choices only.
